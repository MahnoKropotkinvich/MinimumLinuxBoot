# Generic MinimumLinuxBoot for RTL Simulations
GSoC 2026 Project [Generic MinimumLinuxBoot for RTL Simulations](https://summerofcode.withgoogle.com/programs/2026/projects/TBGVWAn6). This project aims to drastically reduce total time spent on waiting for booting when running Linux on [OpenPiton](https://github.com/PrincetonUniversity/OpenPiton) on [Verilator RTL emulator](https://github.com/verilator/verilator).
## Prerequisites
- **build dependencies** for submodules Verilator, qemu and bsc-linux, it is usually accessible from your package manager (`dnf builddep qemu verilator kernel` in Fedora/RHEL, for example) or you can manually install deps according to upstream
- **OpenPiton Verilator C++ emulator**, which can be generated by its `sims` utility (you shouldn't change its memory image schema, since this tool only generates the original one), **note that you MUST change PMP region numbers to 16 or higher**
- **native or cross RISC-V build toolchain**, cross toolchain is accessible from https://github.com/riscv-collab/riscv-gnu-toolchain (**both newlib and Linux**)

## Components
- a forked version of **QEMU**, providing `OpenPiton` RISC-V machine type to match exactly real hardware's peripheral addresses
- **Linux kernel + initramfs** from the `bsc-linux` submodule
- **Python scripts**, for state capture & image schema conversion
- **M-mode stub**, to restore all saved states in memory image
- **ebreak trigger**, built by bsc-linux and installed as `/ebreak_trigger` in the initramfs
- **Makefile**, for toolchain building and automated pipeline
## Usage
1. Ensure all prerequisites are met
1. Init all submodules (`git submodule update --init --recursive`)
2. Build everything and capture (first bsc-linux build is slow):
```bash
make PREFIX=/path/to/cross capture -j$(nproc)
```
or point at another kernel/initrd
```bash
make PREFIX=/path/to/cross KERNEL=/path/to/Image INITRD=/path/to/rootfs.cpio capture
```
The initramfs **MUST** run `/ebreak_trigger` at the checkpoint (`::once:/ebreak_trigger` in inittab).
3. The output dir is under `build/`. The converted memory image is `build/mem.image`
## Notes
- OpenPiton itself is not shipped with this repo, you can build it on your own.
- OpenPiton does not provide an interactive fake UART device either but a read-only one. You can manually modify it into a NS16550-compatible read-write device.
- We only use bsc-linux's kernel and initramfs. Not its firmware and DTS.
- The supported maximum smp number is 16, according to upstream qemu restriction.
